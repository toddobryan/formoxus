## Built and pushed

- `path!(Model.field)` + `Path<T>` — compile-checked paths anywhere, not just
  where a form decorates a field.
- `WireForm<T>` + `Form::{to_wire, absorb, apply_errors}` — the return leg.
  `collect_errors()` finally has a consumer.
- `widget: select { choices: … }` — the widget-argument brace block, and static
  choices end to end.
- `ValueKind::check` — `min_length` / `max_length` / `pattern` / `min` / `max`,
  with 35 inline tests. **Patterns go through `regress`**, not `regex`, so the
  server agrees with the browser about what a `pattern` means; they are wrapped
  `^(?:…)$` because HTML anchors implicitly.

379 tests, `just ci` green.

## The next task, and why nothing works yet

`value_kind()` derives from `T::SHAPE`, so every constraint field is `None`
forever. **The checking is written; nothing sets the constraints.** Three pieces,
in order:

1. **Field-level keys in `form!`** — `bio => { max_length: 500, widget: textarea }`.
   Siblings of `label:`, deliberately NOT inside the widget braces, so a widget
   swap cannot discard them.
2. **Spec → field** — `FieldSpec` gains the constraint fields, `apply_specs`
   copies them onto `FormField`, and `value_kind()` combines the *family* from
   `T` with the *constraints* from `self`. Same route `choices` took, so the
   shape is proven. **Decide first:** one `constraints: Option<Constraints>`
   field or three loose ones, since that is what `with_max_length` /
   `with_pattern` / `with_min` all build against.
3. **The compile-time checks** — see [[const-shape-walk-blocked]], whose
   conclusion reversed: use `T::SHAPE` in a `const {}` block, not marker traits.
   `min_length > max_length` and `pattern`-parses stay in the macro at PARSE
   time, because `expand` has no error channel.

`formoxus/CONSTRAINTS_PLAN.md` has the full three-tier inventory and the settled
calls on `step` (out) and `choices` (stays tier 2).
